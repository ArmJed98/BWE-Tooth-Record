# BWE Tooth Intelligence — แดชบอร์ดวิเคราะห์ฟันบุ้งกี๋

แดชบอร์ดวิเคราะห์การสึกหรอและการเชื่อมพอกฟันรถขุดล้อตัก (Bucket Wheel Excavator) BWE#1 / BWE#2
เปิดดูผ่านหน้าเว็บ GitHub Pages ได้ และดึงข้อมูล **real-time จาก Google Sheet**

---

## 1. ดูแดชบอร์ดผ่านเว็บ (GitHub Pages)

ไฟล์ `index.html` คือหน้าแดชบอร์ด เปิดใช้งานผ่านเว็บโดย:

1. ไปที่ repo บน GitHub → **Settings** → **Pages**
2. ที่หัวข้อ **Build and deployment** → **Source**: เลือก **Deploy from a branch**
3. **Branch**: เลือก branch ที่ต้องการ (เช่น `main`) และโฟลเดอร์ **`/ (root)`** → กด **Save**
4. รอสักครู่ GitHub จะสร้าง URL ให้ในรูปแบบ:

   ```
   https://<username>.github.io/BWE-Tooth-Record/
   ```

> หมายเหตุ: GitHub Pages จะเสิร์ฟจาก branch ที่เลือกไว้ ถ้าตอนนี้งานอยู่บน branch `claude/...`
> ให้ merge เข้า `main` ก่อน หรือเลือก branch นั้นใน Settings → Pages โดยตรง

## 2. การเชื่อมข้อมูล Real-time กับ Google Sheet

แดชบอร์ดดึงข้อมูลสดจาก Google Sheet ผ่าน **gviz** (Google Visualization API)
ทำงานฝั่งเบราว์เซอร์ของผู้เปิดดู จึงอัปเดตอัตโนมัติทุกครั้งที่คุณแก้ Sheet

- ถ้าเชื่อม Sheet ได้ → แสดง 🟢 **ข้อมูลสด** พร้อมเวลาอัปเดต (มุมขวาบน)
- ถ้าเชื่อมไม่ได้ → ใช้ข้อมูลสำรองที่ฝังในไฟล์ และแสดง 🔴
- รีเฟรชอัตโนมัติทุก **5 นาที** หรือคลิกที่ข้อความสถานะเพื่อรีเฟรชทันที

### 2.1 ตั้งค่าใน `index.html`

ค้นหาบล็อก `SHEET_CONFIG` (ในแท็ก `<script>`):

```js
const SHEET_CONFIG = {
  id: '1_HnUI5RIjXqAMwq_ZPVIw1xHLqPN77u-KOP765o_arM',  // Spreadsheet ID ของคุณ
  enabled: true,            // false = ใช้ข้อมูลฝังในไฟล์ (ไม่ดึงจาก Sheet)
  refreshMs: 5 * 60 * 1000, // รีเฟรชอัตโนมัติทุก 5 นาที (0 = ปิด)
  tabs: { summary:'summary', hf1:'hf1', hf2:'hf2', tooth:'tooth', periods:'periods', daily:'daily', life:'life' }
};
```

- `id` = ส่วนกลางของ URL Sheet: `https://docs.google.com/spreadsheets/d/`**`<ID>`**`/edit`
- `tabs` = ชื่อแท็บ (sheet) ในไฟล์ Google Sheet — ต้องสะกดตรงเป๊ะ (ตัวพิมพ์เล็ก)

### 2.2 เปิดสิทธิ์ให้ Sheet เป็นสาธารณะ

gviz อ่านได้เฉพาะ Sheet ที่เปิด public:

- **Share** → **General access** → **Anyone with the link** → **Viewer**

(ทางเลือก: **File → Share → Publish to web** ก็ใช้ได้)

## 3. โครงสร้างแท็บใน Google Sheet ที่ต้องมี

ไฟล์ Google Sheet ต้องมี **7 แท็บ** ชื่อตามนี้ และวางคอลัมน์ตามลำดับนี้
(มีไฟล์ตัวอย่างให้ในโฟลเดอร์ [`sheet-template/`](sheet-template/) — เปิดด้วย Excel/Sheets แล้ว
**คัดลอกค่าไปวาง** หรือ **File → Import** เป็นแท็บได้เลย)

> แถวแรกของทุกแท็บคือ "หัวตาราง" **ยกเว้น** `hf1` และ `hf2` ที่เป็นตารางตัวเลขล้วน (ห้ามมีหัวตาราง)

### แท็บ `summary` — สรุปต่อเครื่อง (2 แถวข้อมูล)
| eq | smu | install | replace | lost | hardface |
|----|-----|---------|---------|------|----------|
| BWE1 | 1012 | 234 | 1122 | 888 | 302 |
| BWE2 | 628 | 234 | 478 | 244 | 624 |

### แท็บ `hf1` และ `hf2` — Heatmap การเชื่อมพอก
ตาราง **18 แถว × 13 คอลัมน์** ค่าระดับ `1`–`3` (แถว = บุ้งกี๋ B1–B18, คอลัมน์ = ฟัน T1–T13)
**ไม่มีหัวตาราง** เริ่มที่ช่อง A1

### แท็บ `tooth` — ข้อมูลรายตำแหน่งฟัน (13 แถว)
| pos | type | hf1 | hf2 |
|-----|------|-----|-----|
| 1 | short | 20 | 48 |
| ... | ... | ... | ... |
- `type` = `short` (ฟันสั้น) หรือ `long` (ฟันยาว)
- `hf1` / `hf2` = จำนวนครั้งเชื่อมพอกรวมของตำแหน่งนั้น แต่ละเครื่อง

### แท็บ `periods` — แนวโน้มตามช่วงเวลา (9 แถว)
| period | gi | lost | install | ma_percent |
|--------|----|----|---------|-----------|
| Jun | 20 | 27 | 207 | 88.46 |
| ... | ... | ... | ... | ... |
- `gi` = เบิกใช้จากคลัง, `lost` = ฟันสูญหาย, `install` = ฟันติดตั้งจริง
- `ma_percent` = % ความพร้อมใช้งาน (กรอกเป็นเปอร์เซ็นต์ เช่น `94.9` หรือสัดส่วน `0.949` ก็ได้)

### แท็บ `daily` — ฟันสูญหายรายวัน
| date | b1 | b2 | … | b18 |
|------|----|----|----|-----|
| 2025-10-01 | 0 | 0 | … | 0 |
- `date` = วันที่ (แนะนำรูปแบบ `YYYY-MM-DD`)
- `b1`–`b18` = จำนวนฟันสูญหายของบุ้งกี๋ที่ 1–18 ในวันนั้น

### แท็บ `life` — อายุการใช้งานสะสม (2 แถว)
| eq | period | gr | gi | lost | ma_percent |
|----|--------|----|----|----|-----------|
| BWE1 | 17/6/2022 - 31/5/2025 | 2808 | 1122 | 888 | 94.87 |
| BWE2 | 23/5/2022 - 3/11/2025 | | 478 | 244 | |

### แท็บ `wear` — การสึก/อายุฟัน (บันทึกความยาวฟันรายครั้งตรวจ)
| date | machine | smu | short_len | long_len | short_threshold | long_threshold | avg_age |
|------|---------|-----|-----------|----------|-----------------|----------------|---------|
| 2024-10-03 | BWE1 | 6567 | 18.16 | 25.15 | 15.5 | 16.5 | 1001 |
- `short_len` / `long_len` = ความยาวเฉลี่ย (cm) ของฟันสั้น/ฟันยาว ณ วันตรวจ
- `short_threshold` / `long_threshold` = เกณฑ์ความยาวที่ต้องเปลี่ยน (สั้น 15.5 · ยาว 16.5)
- `avg_age` = อายุฟันเฉลี่ย (ชั่วโมง) · ความยาวเดิม สั้น 20 / ยาว 28 cm
- มีไฟล์พร้อม import: **`BWE_Tooth_Wear_clean.xlsx`** (แท็บ `wear`)

## 6. เพิ่มรูปฟันจริง (Real Tooth BWE Views) ในหน้า Heatmap

หน้า Heatmap มีช่องแสดงรูปฟันจริง 3 มุม (front / back / side) ทางขวา
เพิ่มรูปได้ผ่านหน้าเว็บ GitHub (ลากวาง ไม่ต้องใช้ git):

1. ตั้งชื่อรูป 3 ไฟล์ในเครื่องให้ตรงนี้ (ตัวพิมพ์เล็ก):
   - `tooth-front.jpg` (มุมหน้า)
   - `tooth-back.jpg` (มุมหลัง)
   - `tooth-side.jpg` (มุมข้าง)
2. ไปที่ repo บน GitHub → เข้าโฟลเดอร์ **`assets/`** → **Add file** → **Upload files**
3. ลากรูปทั้ง 3 วาง → **Commit changes**
4. รอ ~1 นาที แล้วรีโหลดหน้า → รูปจะขึ้นแทนช่อง placeholder

> ถ้ายังไม่อัปรูป หน้าจะแสดง placeholder ไว้ก่อน ไม่พัง · รองรับ `.jpg`

## หมายเหตุทางเทคนิค

- ดึงข้อมูลผ่าน gviz แบบ JSONP (แทรก `<script>`) จึงไม่ติดปัญหา CORS เมื่อ Sheet เปิด public
- ถ้า Sheet ยังไม่พร้อม/เชื่อมไม่ได้ แดชบอร์ดยังแสดงผลได้ด้วยข้อมูลสำรอง (`FALLBACK_DATA`) ที่ฝังในไฟล์
- ส่วน "บันทึกรายการรายวัน" ในหน้าแดชบอร์ดเก็บข้อมูลในเครื่องผู้ใช้ (แยกจากข้อมูล Google Sheet)
